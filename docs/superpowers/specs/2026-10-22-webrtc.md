# Под-проект 6: прямой канал WebRTC — спека

Часть дизайна `2026-10-22-mys-android-design.md` (§2 «Апгрейд на WebRTC»).
Затрагивает все три проекта.

## Протокол (общий для телефона и десктопа)

- Kind содержимого `KIND_SIGNAL = 0x03` внутри `envelope.seal`; тело — UTF-8 JSON:
  `{"t":"offer","sdp":…}`, `{"t":"answer","sdp":…}`,
  `{"t":"cand","c":"candidate:…","mid":"0","idx":0}`.
  Сигналинг идёт внутри E2E-сессии: сервер не видит ни SDP, ни IP. Не
  персистится и не показывается. Старые клиенты отбрасывают неизвестный kind —
  пара остаётся на relay.
- INITIATOR создаёт offer сразу после prime-кадра; DataChannel `mys`,
  ordered/reliable; один wire-кадр `DATA` = одно бинарное сообщение.
- ICE: `stun:<хост сервера>:3478` (если адрес сервера — https/wss). Кандидаты:
  телефон шлёт trickle (`cand`); aiortc кладёт свои в SDP и принимает trickle.
- `CHUNK_SIZE` 64 КиБ у всех (лимит сообщения WebRTC ~256 КиБ); получатель
  берёт размер из `FILE_META`.

## Сессия

- Два транспорта: relay (всегда, держит `PEER_LEFT`) и прямой (если открыт).
  Отправка — по прямому, при ошибке — откат на relay; приём — с обоих (ratchet
  переживает переупорядочивание на стыке через skipped keys).
- Обрыв прямого — сессия жива на relay; INITIATOR повторяет offer через 10 с,
  затем с backoff до 2 мин. Сессия разорвана, только когда мертвы оба пути.
- `DirectLink` — интерфейс в `:p2p` (start/onSignal/restart/close; offer на
  стороне ответчика пересоздаёт PeerConnection). Реализации: `org.webrtc`
  (`stream-webrtc-android`) в `:app`, `aiortc` в десктопе.
- UI: «прямой канал» / «через сервер».

## Десктоп

- `KIND_SIGNAL`, мультитранспортная сессия, `mys_decentralized/webrtc.py` на
  aiortc (необязательная зависимость `[webrtc]`: без неё — только relay).
- `CHUNK_SIZE` 64 КиБ.
- Удаляется мёртвый UDP hole-punch на loopback (`DirectTransport` и пр.); `HELLO`
  с пустыми кандидатами. Wire-типы `PUNCH`/`PUNCH_ACK` остаются в протоколе.

## Сервер

- coturn в режиме STUN-only (`stun-only`, `no-auth`, без relay-портов) на
  `3478/udp`: конфиг и шаги установки в `vsc_web`. Код сервера не меняется.

## Тесты

- `:p2p` JVM: сессия с in-memory прямым транспортом — отправка по прямому,
  откат на relay, сигналы не персистятся, обрыв прямого не рвёт сессию.
- Десктоп: то же + два `P2PService` с aiortc через встроенный rendezvous — канал
  становится прямым, сообщения и файл идут по нему.
- Эмулятор: два `WebRtcLink` в одном процессе; **телефон ↔ десктоп (aiortc)**
  через `vsc_web` на хосте — канал прямой, эхо проходит.

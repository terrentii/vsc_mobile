# МЫС: настройки комнат, диалоги, аватарки

Дата: 2026-10-23. Статус: согласовано с владельцем проекта.
Затрагивает: vsc_web (сервер + веб), vsc_desktop, vsc_mobile.

## Цели

1. Настройки комнаты во всех клиентах (сейчас — только веб-страница создателя).
2. Режим «диалог»: закрытая комната ровно на двух зарегистрированных — аналог личной
   переписки/контакта; удобства для общения вдвоём.
3. Аватарки комнат; в диалоге каждый задаёт своё название и аватарку.
4. Веб: фон «Чертёж» в чате на широких экранах.
5. Телефон (попутно): предложение включить отпечаток и автозапрос отпечатка при открытии.

Обычные (не диалоговые) комнаты ведут себя как сейчас.

## Модель данных (vsc_web)

Миграции — в стиле `app.py` (`ALTER TABLE … ADD COLUMN`, если колонки нет).

| Таблица | Новые колонки |
|---|---|
| `rooms` | `is_dialog BOOLEAN NOT NULL DEFAULT 0`, `dialog_proposed_by VARCHAR(64) NULL`, `avatar VARCHAR(64) NULL`, `avatar_rev INTEGER NOT NULL DEFAULT 0` |
| `room_members` | `title VARCHAR(64) NULL`, `avatar VARCHAR(64) NULL`, `avatar_rev INTEGER NOT NULL DEFAULT 0`, `last_read INTEGER NULL` (Message.id) |
| `users` | `share_read BOOLEAN NOT NULL DEFAULT 1`, `share_online BOOLEAN NOT NULL DEFAULT 1` |

Новая роль участника `invited` (наряду с `godfather`, `member`, `visitor`).

## Правила диалога

- **Пригодна к диалогу** комната, если: не личная (`personal_login` пуст), в ней ровно
  два участника (`room_members`), ни один не `invited`.
- **Диалог** (`is_dialog = 1`): `is_open = 0`, `tg_visible = 0`; вход по коду для
  не-участников запрещён; добавлять/выгонять участников нельзя (409 `dialog`);
  изменить `is_open` нельзя; общее название/аватарка комнаты не используются.
- **Предложить** (`propose`): участник пригодной не-диалоговой комнаты →
  `dialog_proposed_by = он`. Если предложение второго уже лежит — это принятие.
- **Принять** (`accept`): второй участник при наличии чужого предложения, в комнате ровно
  два участника (приглашённый `invited` здесь допустим — так принимается приглашение) →
  `is_dialog = 1`, закрыть комнату, `dialog_proposed_by = NULL`, `invited → member`.
- **Отклонить/отозвать** (`decline`): любой участник → `dialog_proposed_by = NULL`.
  Если это приглашение (есть `invited`) — приглашённый удаляется; комната без
  сообщений удаляется целиком (с каталогом медиа).
- **Выключить** (`disable`): любой участник диалога → `is_dialog = 0` (комната
  остаётся закрытой на двоих, история на месте).
- **Состав изменился** (вход, добавление, кик, выход) → `dialog_proposed_by = NULL`;
  выход участника диалога → `is_dialog = 0`.
- **«Написать пользователю»** (`POST /api/dialogs {login}`): нельзя самому себе (400),
  несуществующий логин — 404; уже есть диалог/приглашение с ним — 200 и эта комната;
  не более 20 приглашений за сутки (429). Создаётся закрытая комната: вызывающий —
  `godfather`, адресат — `invited`, `dialog_proposed_by = вызывающий`.
- **Пока в комнате есть `invited`**, писать в неё не может никто (403 `pending_invite`).

## Названия и аватарки

- Обычная комната: `rooms.name` и `rooms.avatar` — общие, меняет создатель.
- Диалог: `room_members.title` и `room_members.avatar` вызывающего — видит только он.
  По умолчанию название — логин собеседника, аватарка — монограмма (рисует клиент).
- **Эффективные** для вызывающего: `title` (диалог: свой `title` или логин собеседника;
  иначе `name` или null) и `avatar_rev` (0 — аватарки нет).
- Загрузка: PNG/JPEG/WebP ≤ 5 МБ → Pillow: открыть, `ImageOps.exif_transpose`,
  центр-кроп в квадрат, 256×256, сохранить PNG **без метаданных** в
  `rooms/<код>/avatars/<uuid>.png`; старый файл удаляется; `avatar_rev += 1`.
  Битый/не-картинка — 400 `bad_image`. Отдаётся только участникам.
- Зависимость: `Pillow` в `requirements.txt`.

## «Печатает», «прочитано», «в сети» (только диалоги)

- **typing:** клиент шлёт не чаще раза в 3 с; сервер пересылает собеседнику, не хранит,
  не чаще раза в 2 с от участника. Клиент гасит индикатор через 5 с.
- **read:** клиент шлёт `message_id` последнего видимого сообщения (чат открыт, окно
  активно); сервер хранит максимум в `last_read`; при `share_read` пересылает собеседнику.
- **presence:** онлайн = есть хотя бы одно живое соединение (WS приложений или
  Socket.IO веба). При переходе 0↔1 соединений сервер шлёт `presence` во все диалоги
  пользователя (если `share_online`). Время последнего визита не хранится.
- `share_read`/`share_online` (по умолчанию вкл.) — в настройках аккаунта; выключено —
  сервер не шлёт и не отдаёт соответствующие данные. Взаимности нет.
- Мост: события из Socket.IO уходят в WS приложений и наоборот (как сообщения сейчас).

## API (Bearer, префикс `/api`)

Комната (ответ `GET /api/rooms`, `GET /api/rooms/<id>` и мутаций):

```json
{"id": 7, "code": "0123456789", "name": "…|null", "is_direct": false,
 "updated_at": "…", "is_open": false, "is_dialog": true,
 "dialog_proposed_by": "login|null", "role": "godfather|member|visitor|invited",
 "title": "эффективное название|null", "avatar_rev": 3,
 "peer": "login|null", "peer_read": 120, "peer_online": true, "members": 2}
```

`peer` — собеседник в диалоге/приглашении/пригодной комнате на двоих, иначе null.
`peer_read`/`peer_online` — только в диалоге и только если собеседник разрешил, иначе null.
`GET /api/rooms/<id>` дополнительно: `"member_list": [{"login": "…", "role": "…"}]`.

| Метод и путь | Кто | Действие |
|---|---|---|
| `GET /api/rooms/<id>` | участник | комната + `member_list` |
| `PATCH /api/rooms/<id>` `{name?, is_open?}` | создатель, не диалог | общие настройки |
| `POST /api/rooms/<id>/members` `{login}` | создатель, не диалог | добавить (404, если логина нет) |
| `DELETE /api/rooms/<id>/members/<login>` | создатель, не диалог | выгнать (не себя) |
| `POST /api/rooms/<id>/leave` | участник | выйти (создатель — нельзя, 409) |
| `POST /api/rooms/<id>/dialog` `{action}` | участник | `propose`/`accept`/`decline`/`disable` (409 `not_eligible`/`no_proposal`) |
| `POST /api/dialogs` `{login}` | любой | «Написать пользователю» |
| `PATCH /api/rooms/<id>/me` `{title}` | участник диалога | своё название (≤64; пусто — сброс) |
| `PUT /api/rooms/<id>/avatar` multipart `file` | диалог — свой; иначе создатель | загрузить |
| `DELETE /api/rooms/<id>/avatar` | так же | удалить |
| `GET /api/rooms/<id>/avatar` | участник | эффективная PNG (404 — нет); `ETag: "<rev>"` |
| `POST /api/rooms/<id>/read` `{message_id}` | участник диалога | отметка прочтения |
| `GET/PATCH /api/me` `{share_read?, share_online?}` | любой | настройки приватности |

`POST /api/messages` в комнату с `invited` — 403 `pending_invite`.

WS `/ws` — новые кадры сервер → клиент:
`{"type":"room_updated","room_id"}` (настройки/диалог/состав/аватар — клиент
перечитывает комнату), `{"type":"room_removed","room_id"}`,
`{"type":"typing","room_id","login"}`, `{"type":"read","room_id","login","message_id"}`,
`{"type":"presence","room_id","login","online"}`.
Клиент → сервер: `{"type":"typing","room_id"}` (раньше входящие кадры игнорировались).
Новые/удалённые комнаты подписываются/отписываются на лету (`subscribe_user`/аналог).

Socket.IO (веб): те же события `room_updated`, `room_removed`, `typing`, `read`,
`presence`; клиент шлёт `typing {room_id}`; прочтение — `POST /room/<code>/read`.

## Клиенты

**Настройки комнаты** (веб: страница `/room/<code>/settings` вместо `manage`;
десктоп: окно; телефон: экран). Разделы по роли/режиму:
- обычная, создатель: название, аватарка, открыта/закрыта, участники (добавить/выгнать),
  удалить комнату;
- обычная, участник: название, участники (просмотр), покинуть;
- пригодная к диалогу: «Сделать диалогом» / плашка «*логин* предлагает диалог:
  Принять / Отклонить» / «Отозвать предложение»;
- диалог: моё название, моя аватарка, «Выключить диалог», покинуть.
Телефон: локальное «Переименовать» для комнат «Центра» убирается (название — на
сервере); для P2P остаётся.

**Список бесед:** аватарки/монограммы; секция «Приглашения» сверху
(Принять/Отклонить); кнопка «Написать пользователю» рядом с «Новая комната».

**Чат-диалог:** пузыри (свои справа, кобальт; чужие слева), без повтора имени;
шапка — аватар, название, «в сети», «печатает…»; у своих сообщений ✓ (на сервере)
и ✓✓ кобальтом (прочитано: `wire_id ≤ peer_read`). Десктоп переключает журнал на
пузыри только в диалоге; веб — так же; телефон уже с пузырями.

**Веб, «Чертёж»:** `<canvas>` под лентой чата на экранах ≥ 900px: сетка 12px (каждая
5-я жирнее) кобальтом низкой яркости + развёртка 20 с; `prefers-reduced-motion` — без
развёртки; на скрытой вкладке анимация стоит (`requestAnimationFrame`). Без библиотек.

**Аватарки в клиентах:** кэш в памяти по `(room_id, avatar_rev)`; качаются при
отображении; при `avatar_rev = 0` — монограмма.

**Приватность** (настройки аккаунта во всех клиентах): «Показывать, что я прочитал»,
«Показывать, что я в сети».

**Телефон, отпечаток:** после создания хранилища (если датчик доступен) — оверлей
«Входить по отпечатку?»; при включённом отпечатке экран разблокировки сам вызывает
запрос отпечатка при каждом показе; ПИН-код — запасной путь.

## Этапы и проверка

1. **Сервер + веб** (vsc_web): pytest — правила диалога (все переходы и запреты),
   приглашения (лимит, отказ удаляет пустую комнату, запрет писать), права PATCH/
   members/leave, аватарки (EXIF удалён, 256×256 PNG, права, rev), read/typing/presence
   по WS (изоляция `ROOMS_DIR` как в существующих тестах). Веб — ручная проверка.
2. **Десктоп**: синк меты комнат, окно настроек, пузыри/галочки/шапка, приглашения;
   pytest + снимки окон; e2e против живого vsc_web.
3. **Телефон**: `:central` (API, кадры WS) против живого vsc_web; экран настроек,
   список, чат; кадры экранов; отпечаток.
Каждый этап — свой PR (отпечаток — отдельный маленький PR телефона).

# Под-проект 3: P2P через relay — спека

Часть дизайна `2026-10-22-mys-android-design.md` (§2, «Базовый путь»). Эталон —
`vsc_desktop/src/mys_decentralized` (`main`). Цель — переписка и файлы между
телефоном и десктопом через rendezvous/relay (`wss://<сервер>/p2p`).

## Объём

- Протокол байт-в-байт с десктопом: деривация `room_id`/`prs` (NFKC → BLAKE2b
  `person=mys-phrase` → HKDF), кадры `u8 type|u8 flags|u32 len|payload`, все
  типы сообщений, кандидаты.
- Rendezvous: `HELLO{room_id, []}` → `PAIR{role}`; затем relay-транспорт
  (`RELAY{кадр}` в одном бинарном WS-сообщении), `PEER_LEFT` ⇒ обрыв.
- Хендшейк: CPace + `CONFIRM` (HMAC-SHA256 по `mys-confirm`), `sk` и DH Боба из
  ISK, ratchet по роли.
- Сессия: `DATA{seal(kind ‖ body)}`, kind `0x00` текст / `0x01` FILE_META /
  `0x02` FILE_CHUNK; неизвестный kind тихо отбрасывается (задел под сигналинг
  WebRTC). Prime-кадр от INITIATOR, очередь исходящих у RESPONDER до prime,
  битые/повторные кадры отбрасываются, реконнект возобновляет ratchet из
  хранилища, повторный ввод фразы не нужен (сохранённый `prs`).
- Сервис: `startSession(phrase)`, `resolveConversation`, `reconnect`, `send`,
  `sendFile`, `stopSession`, поток событий (сообщение / онлайн-офлайн / ошибка).

## Отличия от десктопа (сознательные)

- **Без UDP hole-punch.** `HELLO` с пустым списком кандидатов, сразу relay:
  у десктопа прямой путь анонсирует `127.0.0.1` и между устройствами не
  работает; десктоп сам откатывается на relay за 1 с. Прямой канал — WebRTC,
  под-проект 6.
- **Состояние ratchet сохраняется до отправки кадра** (десктоп — после): при
  падении между отправкой и записью ключ цепочки не переиспользуется.
- **`CHUNK_SIZE` 64 КиБ** (десктоп — 256 КиБ; получатель берёт размер из
  `FILE_META`, совместимо). Входящий файл получает kind по расширению
  (`image`/`file`), как исходящий.
- Невалидная точка пира в CPace — `PakeException` (у десктопа — сырая ошибка
  ristretto). Таймаут хендшейка 30 с.

## Архитектура

Новый JVM-модуль `:p2p` (чистый Kotlin + coroutines + OkHttp), тестируется без
Android. Хранилище — через интерфейсы `P2PStore`/`SessionStore`; реализация на
vault — `VaultP2PStore` в `:app`, в тестах — память. Адрес rendezvous —
параметр сервиса (домен сменится).

## Тесты

- JVM: протокол, файлы и деривации хендшейка — по векторам из десктопа;
  хендшейк и сессия — два Kotlin-клиента через in-memory транспорт.
- **Интероп (JVM):** Kotlin-клиент ↔ настоящий `P2PService` десктопа
  (`tools/desktop_peer.py`) через настоящий `/p2p` из `vsc_web`, в обе стороны
  ролей; текст, файл 200 КБ. Пропускается без `DESKTOP_PYTHON`/`VSC_WEB_PYTHON`.
- Инструментальный: `VaultP2PStore` на эмуляторе.

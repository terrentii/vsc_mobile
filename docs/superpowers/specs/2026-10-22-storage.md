# Под-проект 2: локальное хранилище — спека

Часть дизайна `2026-10-22-mys-android-design.md` (§3 «Vault»). Эталон — `vsc_desktop/src/mys_storage` (ветка `main`).

## Переносится из десктопа

- Открытый sidecar рядом с БД: соль, параметры KDF, счётчик неудач, `lockout_until`, настройки duress.
- Прогрессивная задержка неверного пароля: `2^n` с, потолок 300 с.
- Опциональный duress-wipe после `threshold` неудач (best-effort перезапись + удаление).
- Ключ БД — 32 байта, в SQLCipher как raw key (`x'…'`); смена пароля — `rekey`.
- Атомарный `receiveMessage`: сообщение + состояние ratchet в одной транзакции.
- Репозитории: settings, conversations (с `p2p_prs`), messages, ratchet.

## Отличия от десктопа (сознательные)

- **Схема — одна миграция v1**, равная итоговой схеме десктопа `main` v7 (без `identities`/`contacts`, `peer_contact_id`, `archived` — не используются). Механизм `PRAGMA user_version` остаётся. БД с десктопом не обменивается.
- **KDF — `crypto_pwhash` libsodium (Argon2id13)**, 128 МиБ, ops=3: память вне Java-кучи (BC Argon2 на 256 МиБ уронит приложение). Параметры в sidecar.
- **Sidecar — `java.util.Properties`**, а не JSON (stdlib, одинаково на JVM и Android).
- Время — `Long` миллисекунды; settings — строки.
- Методы репозиториев только «Центра» (`find_out_by_client_id` и т.п.) — в под-проекте 4.

## Биометрия (крипто-часть)

AES-256-GCM ключ в Android Keystore (`setUserAuthenticationRequired`, `setInvalidatedByBiometricEnrollment`, StrongBox при наличии) оборачивает ключ БД; файл `vault.bio = iv ‖ ct`. Шифр отдаётся наружу для `BiometricPrompt.CryptoObject` (UI — под-проект 5). Инвалидация ключа ⇒ обёртка удаляется, вход по паролю.

## Тесты

- JVM (`app/src/test`): sidecar — запись/чтение, задержки, duress-порог.
- Инструментальные (`app/src/androidTest`, headless-эмулятор из `flake.nix`): создание/открытие, шифрованность файла, неверный пароль и блокировка, duress, смена пароля, атомарный приём, удаление беседы, обёртка Keystore (ключ без требования аутентификации).
